이 문서가 하는 일

지금 계산은 전부 예시 값 위에 서 있다. 실제 값이 들어와야 다시 돌릴 수 있는데, 그 값이 무엇무엇인지와 어떤 형식으로 받아야 하는지를 여기 한 장에 모았다. 아래 §3 폼을 채우면 플러그인이 바로 읽는 프리셋 JSON 이 나온다. 프리셋은 현장 하나의 설정값을 담은 파일이다. 현장 하나가 파일 하나.

아나모픽 정해진 한 지점에서 볼 때만 형상이 바르게 보이도록 영상을 미리 비틀어 두는 방식. 벽이 꺾여 있어도 그 자리에서는 평평한 화면처럼 보인다. 그래서 관람 위치가 필수 입력이다.

0쓰는 법

  1. §1 을 읽고 누구에게 무엇을 물어야 하는지 확인한다.
  2. §2 의 두 가지 결정(재생 방식 · 캘리브레이션 방식)을 먼저 받는다. 이것이 안 정해지면 나머지를 다 채워도 어디로 갈지가 안 정해진다.
  3. §3 폼을 채우고 [JSON 내려받기] 를 누른다.
  4. 나온 파일을 Config/AnamorphicRig/ 에 넣는다. 언리얼에서 Tools > Anamorphic Rig > 프리셋 불러오기 로 고르면 끝.
  5. 또는 파일을 그대로 나에게 주면 계산과 검토까지 돌려 준다.
모르는 값이 있어도 됨

비워 두면 예시 기본값이 들어가고, JSON 의 _notes.assumed 에 가정값으로 기록된다. 나중에 무엇이 확정값이고 무엇이 가정인지 구분할 수 있다.

1필요한 외부 입력 전체 목록

누구에게 받아야 하는지로 묶었다. 필수 가 없으면 계산 자체가 성립하지 않는다. 우리가 정함 은 물어볼 필요 없다.

1.1 PM · 발주처 결정 (도면과 무관, 이것부터)

항목없으면 무슨 일이 생기나
필수 재생 방식
언리얼 실시간 / 플레이어 재생
언리얼 실시간은 현장 PC 가 엔진을 돌려 그 자리에서 화면을 만든다. 플레이어 재생은 미리 변환해 둔 영상 파일을 재생기에 넣는다.		 7단계(워프 메시·PFM)를 만들지 6단계(영상 변환)로 끝낼지가 여기서 갈린다. 반대로 만들면 한 단계를 통째로 버린다
워프 메시는 영상을 벽 모양에 맞춰 미리 휘어 주는 격자, PFM 은 그 휨을 화소 단위 좌표표로 적어 둔 파일 형식이다. 둘 다 프로젝터·엔진이 읽어서 화면을 벽에 맞춘다.
필수 캘리브레이션 방식
카메라 측정(VIOSO 등) / CAD 계산
캘리브레이션은 화면이 실제로 어디에 어떻게 맺히는지 재서 보정값을 만드는 일이다. 카메라로 벽을 찍어 재거나, 도면 수치로 계산해 낸다.		 측정 기반이면 곡면이 부담이 아니고 7단계의 성격도 달라진다. CAD 계산이면 도면 정확도가 곧 결과 정확도다
필수 표시 장치
LED 벽 / 프로젝터 / 둘 다		 프로젝터가 없으면 §3 의 프로젝터 구간을 통째로 비운다
있으면 콘텐츠 제작 주체와 일정 화각과 권장 렌더 크기를 넘겨야 할 상대. 늦게 알면 이미 잘못된 화각으로 렌더돼 있다
화각은 카메라나 눈이 한 번에 담는 각도 범위다. 영상 쪽 화각과 벽의 화각이 다르면 변환이 잘라서 맞추고, 잘린 것보다 원근이 어긋난 것이 더 위험하다.

1.2 도면 (평면도 · 입면도)

상세 설명과 함정은 03-drawing-requirements.md 에 있다. 여기는 목록만.

항목필드비고
필수왼쪽 면 전개 길이 face_b_m라운드 구간을 뺀 직선부만. 투영 길이 아님
전개 길이는 벽면을 따라 자로 잰 길이, 투영 길이는 위에서 내려다본 직선거리다. 꺾인 벽에서 둘은 다르고 전개 길이가 항상 더 길다. 도면 치수선은 보통 투영 길이다.
필수오른쪽 면 전개 길이 face_a_m좌우가 달라도 된다
필수꺾임각 bend_deg0 이면 일직선
필수볼록 / 오목 convex오목이면 수평 화각이 48° 에서 146° 로 폭증한다. 단일 뷰포트로 감당이 안 되고 프로젝터 배치가 통째로 달라진다
뷰포트는 엔진이 한 번에 그려 내는 화면 하나다. 화각이 너무 넓으면 하나로는 못 그리고 여러 개로 쪼개야 한다.
필수코너 라운드 R fillet_r_m실제 시공 R. 진짜 각진 코너면 다중 패널로 모델링한다
필수화면 세로 크기 wall_height_m발광부 기준
발광부는 실제로 빛이 나오는 영역이다. LED 캐비닛의 테두리(베젤)는 뺀 값이라야 한다.
필수관람 바닥에서 화면 하단 base_m눈높이와 같은 기준면에서 잰 값. 벽 지대가 더 낮으면 음수가 정상
필수두 지대의 표고 차 위에 반영빠지면 벽이 통째로 위아래로 밀린 채 계산된다
표고 차는 벽이 선 바닥과 관람자가 선 바닥의 높이 차다. 리그는 둘의 차이만 쓰므로 기준면이 무엇이든 상관없고, 같은 기준면에서 재기만 하면 된다.
있으면캐비닛 분할 도면 —LED 프로세서가 패널별 입력이면 노드를 쪼개야 한다 (미구현, 스펙 대기)
LED 프로세서는 영상 신호를 받아 LED 패널들에 나눠 보내는 장비다. 노드는 클러스터에서 화면 출력을 맡는 PC 한 대를 뜻한다. 프로세서가 입력을 여러 개로 받으면 출력도 그만큼 쪼개서 내보내야 한다.
있으면구조물 간섭 (기둥·조명·스피커) —프로젝터 시선을 가리는 것

1.3 관람 위치 — 도면에 점으로 찍혀 있어야 한다

항목필드비고

1.4 장비 사양

항목필드비고
LED 면픽셀 피치 pitch_mm이것만 있으면 크기에서 해상도를 유도한다
픽셀 피치는 이웃한 화소의 중심 사이 간격이다. 작을수록 촘촘하다. 가로 크기를 피치로 나누면 가로 화소 수가 나온다.
LED 면또는 패널별 실제 해상도 res_x, res_y피치가 구간마다 다르면 이쪽을 직접
프로젝터면대수와 해상도 res_x, res_y세로로 돌려 달면 2160 x 3840 으로 넣는다
프로젝터면렌즈 화각 범위 _notes계산이 낸 필요 화각을 실제 렌즈가 낼 수 있는지 대조
프로젝터면광량 (lm) _notes대수의 하한을 밝기가 정한다. 기하만으로 대수를 정하면 어둡다
lm 은 루멘, 프로젝터가 내는 빛의 총량이다. 한 대가 넓은 면을 맡을수록 같은 광량이 얇게 펴져 어두워진다.
있으면설치 가능 위치 제약 _notes천장 구조, 렌즈 시프트 범위
렌즈 시프트는 프로젝터 본체를 기울이지 않고 렌즈만 옮겨 상을 위아래·좌우로 미는 기능이다. 기울이면 화면이 사다리꼴로 찌그러지므로 시프트로 미는 편이 낫다.

1.5 우리가 정하는 것 (물어볼 필요 없음)

우리가 정함 정면에 둘 이음매(anchor_seam 이음매는 패널과 패널이 만나는 자리, 또는 꺾인 벽의 코너다), 전체 회전(rotate_deg), 워프 메시 분할 수(arc_seg 등), 출력 해상도, 경고 기준값, 블렌드 커브 감마. 폼에서 비워 두면 기본값이 들어간다.

2먼저 받아야 하는 두 결정

여기가 갈림길

언리얼 실시간이면 7단계(프로젝터별 워프 메시 / PFM)가 목적지이고 6단계 영상 변환은 프리뷰용으로만 남는다.
플레이어 재생이면 그 반대다. 6단계로 끝이고 7단계는 만들 필요가 없다. 파이프라인은 이미 완료 상태다.
