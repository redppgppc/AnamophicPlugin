nDisplay 를 얼마나 쓰고 있나

작성 2026-08-31
대상 AnamorphicRig 플러그인 + Moniter_2 프로젝트 · 현황 todo.html · 사용법 02-guide.html

요약
클러스터 골격과 메시 투영만 쓴다 — nDisplay 는 "메시로 워프해서 여러 창에 띄우는 실행기" 로만 쓰고, 그 메시와 블렌드를 만드는 계산은 전부 플러그인이 한다
뜻
좁고 깊게 — 기능면은 좁지만, 쓰는 부분은 엔진 기본값을 안 쓰고 직접 생성한다. 그래서 갈아탈 때 비용이 한쪽에 몰려 있다

1쓰고 있는 것

기능어떻게 쓰나
클러스터 / 노드 / 뷰포트 핵심. .ndisplay 를 플러그인이 직접 생성한다. 노드 분할, 창 사각형, 프라이머리 지정까지.
노드는 창 하나를 그리는 프로세스 하나다. 뷰포트는 그 창 안에서 한 화면 조각이 차지하는 사각형이다.
mesh 투영 정책 워프 메시를 구워 DisplayClusterScreenComponent 에 싣는다.
워프 메시는 평평한 렌더 결과를 실제 벽 모양에 맞게 휘어 주는 변형용 격자다.
DCRA
(DisplayClusterRootActor)		 레벨에 리그로 심고, bOverrideViewportsFromExternalConfig 와 bOverrideTransformsFromExternalConfig 를 켜서 설정 파일이 블루프린트에 구워진 값을 덮어쓰게 한다.
DCRA 는 nDisplay 리그 전체를 담는 액터다. 화면 컴포넌트와 시점이 그 밑에 붙는다.
renderSyncPolicy: ethernet 노드가 둘 이상일 때 프레임 동기. 소프트웨어 배리어다
inputSyncPolicy: ReplicatePrimary 2026-08-31 추가. 프라이머리의 키 상태를 나머지 노드에 복제한다
DefaultViewPoint 카메라 스위트스팟. 오프액시스 절두체가 여기서 나온다.
스위트스팟은 착시가 정확히 맞아 보이는 관람 지점이다.
MRQ 연동
(DisplayClusterMoviePipeline)		 영상 경로. 출력 해상도가 뷰포트와 맞는지 점검하는 메뉴까지 있다.
MRQ 는 무비 렌더 큐. 엔진 화면을 영상 파일로 굽는 기능이다.

파이썬에서 만지는 nDisplay 클래스는 네 개뿐이다: DisplayClusterRootActor, DisplayClusterScreenComponent, DisplayClusterCameraComponent, DisplayClusterConfigurationRectangle.

2안 쓰는 것

엔진의 nDisplay 는 모듈이 28개다. 그중 건드리는 것은 DisplayCluster(코어), DisplayClusterConfiguration(JSON), DisplayClusterProjection(mesh), DisplayClusterMoviePipeline(MRQ) 정도다.

안 쓰는 기능언제 필요해지나
투영 정책 9종
MPCDI, VIOSO, EasyBlend, Domeprojection, Camera, Manual, Link, Reference		 프로젝터 캘리브레이션을 카메라 측정으로 갈 때. todo 3절의 "캘리브레이션 방식" 항목이 이걸 가른다.
캘리브레이션은 화면이 실제 벽에 정확히 맞도록 보정값을 잡는 작업이다. 카메라로 재는 방식과 도면에서 계산하는 방식이 있다.
ICVFX 일체
인너 프러스텀, 라이트 카드, 크로마키, 컬러 그레이딩, Operator 패널		 인카메라 VFX 촬영용이다. 이 프로젝트는 관람용 착시라 해당 없음.
ICVFX 는 LED 벽을 배경으로 두고 카메라로 찍는 촬영 방식이다. 카메라가 보는 영역만 따로 고품질로 그리는 것이 인너 프러스텀이다.
DisplayClusterMedia,
SharedMemoryMedia		 노드 사이로 영상을 실어 나를 때. 여러 PC 로 나누면 필요해진다
DisplayClusterReplication 여러 PC 에서 게임플레이를 맞출 때
RemoteControl · MessageInterceptor · MultiUser 운영 중 원격 제어, 협업 편집
StageMonitoring · Monitor 현장 상태 감시
renderSyncPolicy: nvidia Quadro Sync 하드웨어가 들어올 때. 지금은 소프트웨어 배리어다
Switchboard 여러 PC 를 한 자리에서 띄우고 관리할 때
스테레오 설정에 stereoOffset: None 으로 꺼 두었다. 입체가 필요하면

3엔진에도 있지만 직접 만든 것

여기가 이 프로젝트의 성격을 가장 잘 보여준다. 플러그인 4183줄 중 대부분이 nDisplay 가 받아 갈 입력을 만드는 계산이다.

직접 만든 것줄 수엔진의 대응물
워프 메시 생성 (geometry.py)548 MPCDI / PFM 임포트 경로.
PFM 은 화면의 각 점이 실제 공간 어디인지를 적어 둔 파일 형식이다.
알파 블렌딩 (blend.py)268 MPCDI / VIOSO 가 제공하는 기능.
프로젝터 화면이 겹치는 구간에서 밝기를 서서히 줄여 이음매를 안 보이게 하는 처리다.
프로젝터 배치·밀도·입사각 분석 (projector.py)420 엔진에 없다
영상 변환 (video.py)469 엔진 밖. ffmpeg 직접 호출
설정 생성·실행 (config.py, build.py)801 nDisplay Configurator (에디터 UI).
손으로 찍는 대신 도면 값에서 유도하려고 직접 만들었다
그래서

nDisplay 는 실행기 역할만 한다. 워프 메시와 블렌드를 만드는 계산은 전부 플러그인 쪽이다. 이 구조의 장점은 도면 값이 바뀌면 숫자 하나 고쳐서 전부 다시 뽑을 수 있다는 것이고, 단점은 엔진이 제공하는 캘리브레이션 생태계를 못 쓴다는 것이다.

4이 선택이 언제 뒤집히나

7단계(워프 메시 / PFM 출력)를 어떻게 가느냐가 비율을 바꾼다.

캘리브레이션 방식결과
카메라 측정 (VIOSO 등) blend.py 와 워프 메시 생성이 통째로 엔진 정책으로 대체된다. 투영 정책이 mesh 에서 VIOSO / MPCDI 로 바뀐다. 곡면이 부담이 아니게 된다
CAD 계산 (지금 방식) 지금 구조 그대로. 대신 도면 정확도가 곧 화면 정확도가 된다

todo 3절의 "캘리브레이션 방식" 이 아직 미확인인 이유가 이것이다. 이 한 줄이 플러그인 절반의 운명을 정한다.
