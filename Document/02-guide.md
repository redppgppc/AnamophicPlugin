## 1. 한 줄 요약

**특정 위치에 선 사람의 눈에만 착시가 맞게 보이도록, 꺾인 LED 벽에 나갈 영상을 미리 찌그러뜨린다.**

코엑스 파도(SM타운 앞 전광판)와 같은 원리다.

```
        벽 (위에서 본 그림, 90도로 꺾임)

              ┌──────────┐
             ╱            ╲
            ╱              ╲       <- 실제 LED 벽. 물리적으로 꺾여 있다
           ╱                ╲
          ╱                  ╲

                   ●
              스위트스팟
        여기 선 사람 눈에만 정확하다
```

벽은 꺾여 있는데 영상은 평평한 사각형 파일이다. 그냥 틀면 코너에서 그림이 접혀 보인다.
그래서 **미리 반대로 찌그러뜨린 영상**을 만들어 벽에 넣는다. 그러면 스위트스팟에서
볼 때 원래 그림으로 펴져 보이고, 화면이 공간을 뚫고 나오는 것처럼 보인다.

## 2. 설치

플러그인은 순수 파이썬이다. 컴파일도, 비주얼 스튜디오도 필요 없다.

```
1. Plugins/AnamorphicRig/ 를 대상 프로젝트의 Plugins/ 에 복사
2. 프로젝트 설정 > 플러그인 에서 Python Editor Script Plugin 켜기
3. 에디터 재시작
4. Tools > Anamorphic Rig 메뉴 확인
```

`nDisplay` 플러그인도 켜져 있어야 한다. 영상 변환에는 **ffmpeg 이 PATH 에** 있어야 한다.

설정값은 대상 프로젝트의 `Config/AnamorphicRig/*.json` 에 프리셋으로 저장된다.
플러그인 자체는 건드리지 않으므로 현장마다 프리셋만 늘려 가면 된다.

---

## 3. 메뉴 한 바퀴

`Tools > Anamorphic Rig` 아래 세 묶음이다.

### 프리셋

| 항목 | 하는 일 |
|---|---|
| **설정 편집** | 설정을 **도킹 탭**으로 연다. 모달이 아니라 뷰포트를 보면서 만질 수 있다 |
| 프리셋 불러오기 | 저장된 현장 목록에서 골라 활성으로 삼는다 |
| 프리셋 다른 이름으로 저장 | 지금 값을 새 이름으로 복사한다 |

설정 탭은 **자동 저장이 아니다.** 탭 안 `실행` 항목의 **저장** 버튼을 눌러야 JSON 에 남는다.
탭 맨 위 `00 프리셋` 에 지금 편집 중인 프리셋 이름이 보인다. **저장은 그 이름으로 간다** —
도중에 다른 프리셋을 불러와도 마찬가지다.

### 벽

| 항목 | 하는 일 |
|---|---|
| **형상 점검** | 크기·비율·화각·입사각과 경고를 낸다. 값 바꿀 때마다 누른다 |
| **평면도 보기 / 지우기** | 에디터 뷰포트에 평면도를 그린다. 다시 누르면 지우고 카메라도 되돌린다 |
| **벽 만들기** | 워프 메시 + nDisplay 리그 + 바닥 + PlayerStart 를 현재 레벨에 만든다 |
| 클러스터 실행 | nDisplay 창을 별도 프로세스로 띄운다 |

같은 네 가지가 설정 탭 안 `실행` 항목에도 버튼으로 있다. 거기서 누르면
**저장하지 않은 편집 중인 값**으로 돈다. 값을 바꿔가며 바로 시험할 때 쓴다.

### 영상

| 항목 | 하는 일 |
|---|---|
| **영상 변환 (아나모픽)** | 받은 영상을 벽 형상에 맞게 역왜곡한다 -> `_curved.mp4` |
| 영상 변환 (전개만) | 꺾임 보정 없이 비율만 맞춘다 -> `_wall.mp4` |
| **눈 시점으로 되돌려 보기** | 벽에 넣을 파일을 받아 스위트스팟에서 뭐가 보일지 계산 -> `_eye.mp4` |
| 무비 렌더 큐 점검 | MRQ 출력 해상도가 뷰포트와 맞는지 본다 |
| 렌더 결과 좌우 합치기 | `Saved/MovieRenders` 의 뷰포트별 파일을 패널 순서대로 가로로 붙인다 |
| 출력 폴더 열기 | 변환 결과가 쌓이는 `Content/Movies` |

## 4. 기본 흐름

```
설정 편집 에 도면 값 입력
      ↓
[저장]          크기·비율이 도면과 맞는지 확인
      ↓
[형상 점검]     입사각·밀도 경고 확인
      ↓
[평면도 보기]   법선 방향과 이음매를 눈으로 확인
      ↓
격자 영상으로 영상 변환(아나모픽) -> 눈 시점으로 되돌려 보기
      격자가 곧게 펴지면 형상이 맞은 것.  <- 최종 검산
      ↓
[벽 만들기]  ->  [클러스터 실행]
```

값을 바꿨을 때 다시 돌려야 하는 범위:

| 바꾼 것 | 다시 할 것 |
|---|---|
| 경고 기준, 영상 경로 | 없음 (다음 동작이 알아서 읽는다) |
| 스위트스팟, 형상, 해상도 | **벽 만들기** (메시와 리그가 형상을 굽고 있다) |
| 형상 | 영상도 **다시 변환** (워프 맵이 형상에 묶여 있다) |

## 5. 벽 형상 정하기

`01 벽 종류` 의 **꺾인 벽 (한 장 연속)** 스위치가 나머지 항목을 갈라 놓는다.

### 꺾인 벽 (한 장 연속)

연속된 한 장이 코너에서 둥글게 꺾이는 벽. 실제 현장의 본편.

| 필드 | 뜻 |
|---|---|
| 왼쪽 / 오른쪽 면 길이 | **전개 길이**. 라운드 구간은 뺀 직선 구간만 |
| 꺾임 (도) | 0 이면 일직선 |
| 볼록 | 코너가 관람자 쪽으로 튀어나오면 켠다 |
| 라운드 반경 R | 실제 시공 R. 호 길이는 `R x 꺾임각(rad)` 으로 자동 계산 |
| 세로 크기 | 발광부 기준 |
| 관람 바닥에서 벽 하단 | 아래 6절 참고 |

좌우 면 길이는 **달라도 된다.**

### 다중 패널

평평한 화면 여러 장을 이어 붙인 것. 크기도 해상도도 장마다 달라도 된다.

패널 목록은 **관람자 기준 왼쪽부터**, 이음매는 패널보다 정확히 하나 적다.

체인에서 떨어진 보조 화면은 `체인에서 분리` 를 켜고 평면 좌표와 법선 방향을 직접 준다.

> **세로는 전 구간이 같아야 한다.** 패널마다 높이나 세로 위치가 다르면 전개 영상이
> 직사각형이 아니게 되어 영상 변환을 할 수 없다. 형상 점검이 막는다.

### 용어 주의: "라운드"

도면에서 "라운드"는 보통 **코너의 모따기 반경**을 말한다. 벽 전체가 원호라는 뜻이 아니다.
이 플러그인의 꺾인 벽은 `직선 + 원호 + 직선` 이다.

## 6. 높이의 기준면

`관람 바닥에서 벽 하단` 과 `눈높이` 는 **반드시 같은 기준면**에서 재야 한다.
리그는 둘의 **차이만** 쓰기 때문에 기준면이 무엇인지는 상관없다.

관람 지대가 벽 지대보다 3 m 높고, 벽 하단이 제 지대에서 5 m, 눈높이 1.6 m 인 경우:

| 기준면 | 벽 하단 | 눈높이 | 결과 |
|---|---|---|---|
| **관람자가 서는 바닥** | **2.0** | **1.6** | +0.40 m |
| 벽이 선 지대 | 5.0 | 4.6 | +0.40 m |
| 절대 표고 EL±0 | 17.0 | 16.6 | +0.40 m |

셋 다 같다. **권장은 관람자가 서는 바닥**이다. `눈높이` 가 실제 값으로 남아 읽기 쉽고,
`바닥 만들기` 가 까는 격자 바닥이 관람자가 실제로 서는 면과 일치한다.

벽 지대가 더 낮으면 값이 음수가 된다. 정상이다.

## 7. 스위트스팟이 정면이 아닐 때

관람 공간이 벽의 대칭축 위에 없는 경우가 흔하다. 통로가 한쪽으로 치우쳐 있거나,
반대편이 건물에 막혀 있거나.

`좌우 치우침 (m)` 에 대칭축에서 벗어난 거리를 넣는다 (+ 가 오른쪽).

치우치면 좌우 화각이 비대칭이 되고, 먼 쪽 끝의 **입사각이 나빠진다.** 형상 점검이
경고를 낸다. 그 끝은 화소가 가로로 뭉개져서, 중요한 내용을 두면 안 된다.

## 8. 영상 변환

세 가지 산출물이 있고 서로 대체할 수 없다.

```
원본 ──(아나모픽)──> _curved.mp4 ──[벽에 넣음]──> 눈: 곧게 펴짐   착시 성립
  │
  └──(전개만)──────> _wall.mp4   ──[벽에 넣음]──> 눈: 코너에서 꺾임

           '눈 시점으로 되돌려 보기' 는 위 "눈:" 부분을 파일로 뽑아 주는 시뮬레이터.
           벽에 넣는 파일이 아니라, 벽 없이 검증하는 용도다.
```

### `_wall` 과 `_curved` 의 차이 (제일 중요)

격자로 직접 만들어 본 결과다. 빨간 세로선이 **벽의 코너 위치**다.

![_wall 과 _curved 비교](images/wall-vs-curved.png)

| | `_wall.mp4` | `_curved.mp4` |
|---|---|---|
| **하는 일** | 비율만 맞춤 (크롭) | 벽 형상 + 스위트스팟을 계산해 **역왜곡** |
| **파일 자체 모습** | 원본과 거의 같음 [1] | 심하게 찌그러져 보임 [2] |
| **벽에 걸고 스위트스팟에서** | 코너에서 **꺾여 보임** [3] | **곧게 펴짐** [4] <- 착시 성립 |
| **관람 거리·치우침·R 영향** | 없음. 비율만 봄 | 전부 받음 |
| **용도** | 로고, 자막, 사람이 돌아다니는 벽 | **본편.** 코엑스 파도 효과 |

- **[1] -> [3]**: 파일은 멀쩡한데 눈으로 보면 빨간 선에서 그림이 접힌다. 건물 모서리처럼
  보인다. 착시가 아니라 그냥 "꺾인 벽에 붙은 그림"이다.
- **[2] -> [4]**: 파일은 괴상하게 찌그러져 있는데 눈으로 보면 격자가 곧게 펴진다.
  벽이 꺾인 게 사라지고 하나의 평평한 창처럼 보인다.

아나모픽은 **한 지점을 위해 나머지를 희생하는** 방식이다. 관람 동선이 정해져 있지 않으면
전개만이 맞다.

### 검증하는 법

벽이 없어도 확인할 수 있다. 이게 이 플러그인의 검산이다.

```
격자.mp4 → 영상 변환(아나모픽) → 격자_curved.mp4
격자_curved.mp4 → 눈 시점으로 되돌려 보기 → 격자_curved_eye.mp4
```

두 번째 결과가 **원본 격자와 똑같이 곧게** 나오면 맞는 것이다.
대조군으로 `_wall` 을 되돌려 보면 건물 모서리처럼 확 꺾여 보인다.

### 리맵 캐시

변환 맵은 만드는 데 오래 걸려서 `%TEMP%\arwarp_*.pgm` 에 캐시된다.
키는 `geometry.py` 의 `geom_key()` 다.

> **형상 knob 을 새로 추가하면 반드시 `geom_key()` 에도 넣을 것.**
> 빠뜨리면 값을 바꿔도 낡은 맵이 조용히 재사용된다. 실제로 한 번 발생했다.

## 9. 아나모픽은 어떻게 계산되나

여기부터는 원리다. 안 읽어도 쓸 수 있지만, 경고 메시지의 뜻을 알려면 필요하다.

### 9.1 핵심은 나눗셈 두 번

스위트스팟을 원점에 두고 정면을 +X 라 하자. 벽의 어떤 점이 `(x, y, z)` 에 있을 때,
그 점이 **눈에 어느 방향으로 보이는지**는 이렇게 정해진다.

```
Xv = y / x          가로 방향
Zv = z / x          세로 방향
```

관람 거리는 정규화 과정에서 상쇄되므로 1 로 두고 계산한다. 눈에 보이는 그림은
방향만으로 결정되기 때문이다. **이 나눗셈 두 번이 전부다.** 나머지는 전부 이걸
어디에 어떻게 적용하느냐의 문제다.

같은 크기의 물체라도 `x` 가 크면(멀면) `Xv` 가 작아진다. 벽이 꺾여 멀어지는 구간은
눈에 좁게 보인다. 그 구간을 **미리 넓게 그려 두면** 눈에서 원래 폭으로 돌아온다.
이게 사전 왜곡이다.

### 9.2 세 좌표계

헷갈리기 쉬운 부분이라 이름을 붙여 둔다.

| 이름 | 무엇인가 | 크기 |
|---|---|---|
| **전개 좌표 `u`** | 벽면을 따라 왼쪽 끝부터 잰 거리 (cm) | 0 .. `developed()` |
| **벽 이미지** | 실제로 벽에 붙는 직사각형 파일 | `out_w x out_h` |
| **가상 평면** | 스위트스팟에 세운 가상의 평평한 스크린 | `vw x vh` |

`_curved.mp4` 는 **벽 이미지**다. 눈에 보이는 그림은 **가상 평면**이다.
변환이란 가상 평면의 그림을 벽 이미지로 옮겨 그리는 일이다.

```
   원본 영상  ──> 가상 평면에 붙임 ──> 벽 이미지로 되찍음 ──> _curved.mp4
                  (평평한 그림)        (remap)
```

### 9.3 워프 맵

ffmpeg 의 `remap` 필터는 **역방향 매핑**을 받는다. "출력의 이 픽셀은 입력의 어디서
가져오냐"를 픽셀마다 적어 준 맵 두 장(가로/세로)이다.

벽 이미지의 픽셀 `(px, py)` 에 대해:

```
u      = (px + 0.5) / mw * W           그 열이 벽의 어느 위치인가
(x, y) = plan_point(u)                 그 위치의 평면 좌표
map_x  = (y/x - x0) * kx               가상 평면의 몇 번째 열인가

z      = zt - (py + 0.5) / mh * H      그 행의 실제 높이 (벽면 위)
map_y  = (z1 - z/x) * kz               가상 평면의 몇 번째 행인가
```

`x0`, `z1`, `kx`, `kz` 는 벽 전체를 훑어서 구한 화면 경계와 배율이다.

여기서 눈여겨볼 것: **`map_x` 는 열에만 의존하고, `map_y` 는 `z` 곱하기 `1/x` 다.**
열마다 `1/x` 를 미리 구해 두면 행마다 곱셈 한 번으로 끝난다. numpy 없이도 견딜 만한
이유가 이 구조 덕이다.

맵은 **16비트 PGM** 으로 쓴다. PGM 규격이 빅엔디안이라 x86 에서는 바이트를 뒤집어
저장해야 한다. 안 그러면 맵이 통째로 난수처럼 보인다.

### 9.4 왜 크게 뜬 뒤 줄이나

`remap` 은 **최근접 샘플링뿐**이다. 그대로 쓰면 벽 끝처럼 늘어나는 구간에서 계단이 심하게 진다.

그래서 출력의 2배(`CURVED_SS = 2`)로 맵을 만들어 되찍은 뒤 `lanczos` 로 줄인다.
느려지지만 결과가 확실히 낫다.

### 9.5 가상 평면의 크기 — `mag`

가상 평면을 너무 작게 잡으면 벽 끝에서 원본 픽셀이 모자라 뭉개진다.
그래서 **벽의 양 끝이 1:1 이 되도록** 크기를 잡는다.

```python
mag = max((2d/W) / (s(W-d) - s(W-3d)),      # 오른쪽 끝
          (2d/W) / (s(3d)   - s(d)))        # 왼쪽 끝
```

`s(u)` 는 벽 위치 `u` 가 화면에서 차지하는 정규화 가로 좌표다.
분자는 전개 좌표에서의 균등한 간격, 분모는 그 간격이 **화면에서** 얼마나 되는지다.

벽 끝이 시선에 스칠수록 분모가 작아지고 `mag` 가 커진다. 즉 **입사각이 나쁠수록
가상 평면이 커지고 변환이 무거워진다.** 이건 낭비가 아니라 그 구간에서 실제로
그만큼의 원본 해상도가 필요하다는 뜻이다.

### 9.6 안전 세로 밴드

이게 실무에서 제일 자주 물어보는 경고다.

벽의 윗변은 눈에 `zt/x` 높이로 보인다. **`x` 가 열마다 다르므로 윗변이 화면에서
수평선이 아니다.** 벽이 멀어지는 구간은 위아래로 좁아 보인다.

```
   눈에 보이는 벽의 윤곽 (과장)

   ─────╲                    ╱─────     <- 윗변: 끝으로 갈수록 내려온다
         ╲__________________╱
         ┌──────────────────┐
         │   안전 세로 밴드  │           <- 벽 어느 지점에서도 잘리지 않는 구간
         └──────────────────┘
         ╱                  ╲
   ─────╱                    ╲─────     <- 아랫변: 끝으로 갈수록 올라간다
```

가상 평면은 이 윤곽을 다 덮는 직사각형이라, **바깥쪽 위아래는 벽이 없는 영역**이다.
거기에 놓인 그림은 벽 어딘가에서 잘려 나간다.

`band` 는 벽 전 구간에서 잘리지 않는 세로 구간의 비율이다. 영상 변환 때 이 값을
찍어 주고, 기준(`안전 세로 밴드 경고 (%)`, 기본 60%) 미만이면 경고한다.

> **중요한 내용(로고, 자막, 얼굴)은 이 밴드 안에 넣어야 한다.**
> 밴드가 좁다는 건 벽이 가로로 길고 화각이 넓다는 뜻이다. 형상의 성질이지 버그가 아니다.

### 9.7 입사각과 화소 밀도

**입사각**은 시선과 벽면이 이루는 각이다. 90도면 정면으로 마주 본다.
작을수록 벽이 시선에 스치듯 놓인다.

입사각이 작은 구간은 눈에 **가로로 압축돼** 보인다. 벽에서는 100 cm 인 것이 눈에는
10 cm 폭으로 보이는 식이다. 그 구간은:

- 사전 왜곡에서 심하게 늘려야 하고 (원본 해상도를 많이 먹는다)
- 실제 화면에서는 화소가 가로로 뭉개져 보인다

기본 경고 기준은 20도다. 그 아래 구간에는 세밀한 내용을 두지 않는다.

**화소 밀도**(px/cm)는 실제 LED 의 화소가 얼마나 촘촘한가다. 구간마다 피치가 다르면
전개 영상 한 장이 구간별로 다른 밀도로 표시된다. 기본 2배 이상 차이나면 경고한다.

### 9.8 되돌려 보기는 어떻게 계산되나

`눈 시점으로 되돌려 보기` 는 워프의 **정확한 역방향**이다.

화면의 가로 방향 `Xv` 를 주면 그 시선이 벽의 어느 전개 위치에 닿는지 찾아야 한다.
`y/x` 가 `u` 에 대해 단조증가라서 **이분법**으로 60회 반복해 푼다.

```python
def solve_u(xv):
    lo, hi = 0.0, W
    for _ in range(60):
        mid = (lo + hi) / 2.0
        px, py = w.plan_point(mid)
        if py / px < xv:  lo = mid
        else:             hi = mid
    return (lo + hi) / 2.0
```

세로는 그 방향의 시선이 벽면과 만나는 높이 `z = Zv * x` 를 구해, 벽의 위아래 범위를
벗어나면 **65535** 라는 범위 밖 값을 넣는다. `remap` 이 그 자리를 `fill` 색으로 칠한다.
되돌려 본 영상의 위아래 검은 부분이 바로 그 영역이다 — 9.6 의 밴드 바깥이다.

### 9.9 왜 워프 메시가 따로 필요한가

nDisplay 의 `Screen` 컴포넌트는 **항상 평면**이다. 꺾인 벽을 표현할 수 없다.

그래서 꺾인 벽은 `mesh` 투영 정책을 쓰고, 전개 길이로 UV 를 매긴 스태틱 메시를 굽는다.

```python
md.set_vertex_position(v, unreal.Vector(x, y, z0 + H * f))
md.set_vertex_instance_uv(inst, unreal.Vector2D(u / W, 1.0 - f), 0)
                                              ↑
                        가로 UV 는 전개 좌표를 그대로 쓴다
```

UV 가 전개 길이에 비례하므로, 벽 이미지를 그대로 붙이면 **호 구간에서도 실측 길이대로**
펴진다. 원기둥 UV 를 쓰면 이게 어긋난다.

영상 플레이트도 **같은 메시를 한 벌 더** 쓴다. 평면 플레이트를 쓰면 시선이 벽에 닿는
지점과 플레이트에 닿는 지점이 달라서, 이 현장 규모에서는 최대 6 m 어긋난다.

다중 패널은 패널마다 Screen 컴포넌트를 따로 두므로 워프 메시가 필요 없다.
다만 영상 플레이트용으로는 여전히 하나 굽는다.

## 10. 다중 패널 영상 출력

MRQ 로 렌더하면 **뷰포트마다 파일이 하나씩** 나온다. 벽에 넣을 파일은 한 장이므로 붙여야 한다.

```
1. Tools > Anamorphic Rig > 렌더 결과 좌우 합치기
     Saved/MovieRenders 의 vp_*.mp4 를 패널 순서대로 → ...merged.mp4
2. 설정 편집 > 05 출력 > 영상 파일 = 그 merged.mp4
3. 벽 만들기
```

붙이는 순서는 **설정의 패널 순서**다. 파일명 알파벳순이 아니다
(`Center`/`Left`/`Right` 같은 이름이면 알파벳순은 가운데부터가 된다).
로그에 붙이는 순서를 찍어 주니 확인할 것.

> **이음매에 틈(`gap`)이 있으면** 붙인 띠가 그 폭만큼 어긋난다. 전개 길이에는 틈이
> 있는데 패널 화소에는 없기 때문이다. `gap=0` 이면 정확히 맞는다.

## 11. 실전에서 걸린 것들

### 무비 렌더 큐로 구웠는데 크기가 안 바뀐다

**MRQ 는 `.ndisplay` 파일을 읽지 않는다.** 레벨에 놓인 DCRA 블루프린트에 구워진
뷰포트 Region 을 그대로 출력 해상도로 쓴다
(`DisplayClusterMovieGraphRenderCameraSource_Math.cpp`).

해상도를 바꿨으면 **벽 만들기를 한 번 돌려야** DCRA 에 반영된다.
`무비 렌더 큐 점검` 이 지금 값을 보여 준다.

### 렌더 후 DCRA 위치가 계속 바뀐다

레벨 시퀀스에 DCRA 를 물고 있는 **Transform 트랙**이 있으면 렌더할 때마다 위치를
덮어쓴다. 트랙을 지우거나 Restore State 를 켠다.

### 벽 만들기에서 에디터가 죽는다

```
A FRenderResource was deleted without being released first!
```

이미 렌더되고 있는 스태틱 메시를 에디터 안에서 다시 빌드하면 렌더 리소스가 해제되지
않는다. 지금은 메시 에셋을 **지우고 새로 만드는** 경로로 우회한다. 그래도 실패하면
다른 레벨이나 액터가 그 메시를 참조하고 있는 것이다.

### 벽이 통째로 까맣게 나온다

백페이스 컬링. `06 고급 > 면 뒤집기` 를 켠다.

### 영상이 위아래로 뒤집혀 보인다

`06 고급 > UV 상하 뒤집기` 를 끈다.

### 평면도가 안 그려진다

에디터 뷰포트는 실시간 모드가 아니면 무효화될 때만 다시 그린다. 지금은 그린 뒤
`editor_invalidate_viewports()` 를 부르므로 바로 보여야 한다. 안 보이면 카메라가
딴 데를 보고 있는지 확인 — 평면도 보기가 카메라를 자동으로 맞춘다.

### 좌상단에 빨간 글씨가 뜬다

nDisplay 의 온스크린 경고다. `05 출력 > 디버그 오버레이 숨김` 으로 끈다.
다만 **모든 경고가 같이 꺼진다.** 개발 중에는 켜 두는 쪽이 안전하다.

### 클러스터 창 크기가 이상하다

작업표시줄 자동 숨김과 디스플레이 배율 100% 를 확인한다.
