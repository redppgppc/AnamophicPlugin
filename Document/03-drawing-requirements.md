# 도면 요구사항 — 리그 설정에 필요한 최소 정보

AnamorphicRig 플러그인의 설정값을 도면만 보고 채우려면 아래 정보가 필요하다.
각 항목 끝의 `코드체`는 대응하는 설정 필드 이름이다.

---

## 0. 가장 중요한 세 가지

도면을 잘못 읽어서 생기는 사고는 거의 이 셋 중 하나다.

**1) 전개 길이 vs 투영 길이**

도면의 치수선은 보통 **투영 길이**(위에서 내려다본 직선거리)다. 우리가 필요한 건
**전개 길이**(벽면을 따라 자로 잰 길이)다. 꺾인 벽에서 둘은 다르다.

```
        투영 길이 (도면 치수선)
      |<--------------------->|
      +-----------.
                   \              전개 길이 = 벽면을 따라 잰 길이
                    \             언제나 투영 길이보다 길다
                     +
```

도면에 투영 길이만 있으면 꺾임각과 함께 줘야 역산이 된다. 애매하면 **현장에서 자로 잰
값**을 우선한다.

**2) 발광부 vs 캐비닛 외곽**

LED 캐비닛에는 보통 테두리(베젤)가 있다. 우리에게 필요한 건 **실제로 빛이 나오는 영역**의
크기다. 도면 치수가 어느 쪽인지 반드시 명시할 것.

**3) 사양서 vs 실측**

캐비닛 개수 x 카탈로그 치수로 계산한 값과 실제 시공 결과는 몇 cm 씩 다르다.
착시는 그 몇 cm 에서 깨진다. 실측값을 받는다.

## 1. 평면도 (필수)

### 꺾인 벽 한 장인 경우

| 필요한 것 | 필드 | 비고 |
|---|---|---|
| 왼쪽 면 전개 길이 | `face_b_m` | **라운드 코너 구간을 뺀** 직선 구간만 |
| 오른쪽 면 전개 길이 | `face_a_m` | 위와 같음. 좌우가 달라도 된다 |
| 꺾임각 | `bend_deg` | 도면에서 읽은 각. 0 이면 일직선 |
| 볼록 / 오목 | `convex` | 코너가 관람자 쪽으로 튀어나오면 볼록 |
| 라운드 코너 반경 R | `fillet_r_m` | 실제 시공 R. 각진 코너면 아주 작은 값 |

면 길이는 **접점까지**다. 호 구간은 R 과 꺾임각에서 자동으로 나온다
(`호 길이 = R x 꺾임각(rad)`). 도면에 전체 길이만 있으면 R 을 같이 줘야 분해된다.

### 여러 장을 이어 붙인 경우

패널마다:

| 필요한 것 | 필드 |
|---|---|
| 이름 (도면 부호) | `name` |
| 가로 (발광부 실측) | `width_m` |
| 세로 (발광부 실측) | `height_m` |
| 바닥에서 화면 하단까지 | `panel_base_m` |

이음매마다 (패널보다 정확히 하나 적다):

| 필요한 것 | 필드 |
|---|---|
| 앞 패널에서 몇 도 꺾이는가 | `turn_deg` |
| 볼록 / 오목 | `convex` |
| 앞 패널 끝과의 틈 | `gap_m` |

체인에서 떨어진 패널(별도 위치의 보조 화면)이 있으면 그것만 평면 좌표와 법선 방향을
직접 준다 (`free_x_m`, `free_y_m`, `free_yaw`).

**패널 순서는 관람자 기준 왼쪽부터**다. 도면에 좌우가 명확히 표시돼야 한다.

## 2. 입면도 / 단면도 (필수)

| 필요한 것 | 필드 | 비고 |
|---|---|---|
| 바닥에서 화면 하단까지 | `base_m` (꺾인 벽) / `panel_base_m` (패널마다) | 벽에 매달리면 이 값이 크다 |
| 화면 세로 크기 | `wall_height_m` (꺾인 벽) / `height_m` (패널마다) | 발광부 기준 |

**두 벽 종류의 기준이 같다.** 바닥에서 화면 하단까지 잰 값을 그대로 넣으면 된다.
환산할 것이 없다.

> v1 프리셋은 패널 세로 위치를 `center_z_m` (눈높이 기준, 화면 **중심**) 으로 적었다.
> 꺾인 벽과 기준이 달라 도면 값을 그대로 넣을 수 없었다. v2 에서 통일했고, 옛 프리셋은
> 불러올 때 자동 변환된다 (`settings.migrate`).

세로는 **전 구간이 같아야 한다.** 패널마다 높이나 세로 위치가 다르면 전개 영상이
직사각형이 아니게 되어 영상 변환을 할 수 없다. 다르다면 도면에 그 사실이 명시돼야 한다.

### 벽이 선 지대와 관람 지대의 높이가 다를 때

리그는 **벽 하단 높이와 눈높이의 차이만** 쓴다. 그래서 기준면이 무엇이든 상관없고,
**둘을 같은 기준면에서 재기만 하면 된다.**

관람 지대가 벽 지대보다 3 m 높고, 벽 하단이 제 지대에서 5 m 위, 눈높이 1.6 m 인 경우:

| 기준면 | 벽 하단 | 눈높이 | 결과 (눈 기준 벽 하단) |
|---|---|---|---|
| 관람자가 서는 바닥 | **2.0** | **1.6** | +0.40 m |
| 벽이 선 지대 | 5.0 | 4.6 | +0.40 m |
| 절대 표고 EL±0 | 17.0 | 16.6 | +0.40 m |

셋 다 같다. **권장은 첫 번째, 관람자가 서는 바닥**이다.

- `눈높이` 가 실제 눈높이(1.6)로 남아 읽기 쉽다
- `바닥 만들기` 가 까는 격자 바닥이 관람자가 실제로 서는 면과 일치한다.
  다른 기준을 쓰면 바닥이 엉뚱한 높이에 그려져 착시 판단을 방해한다
- 벽 지대가 더 낮으면 값이 **음수**가 된다. 정상이고, 하한 제한도 없다

도면에는 **두 지대의 표고 차**가 반드시 표시돼야 한다. 이게 빠지면 벽이 통째로
위아래로 밀린 채 계산되고, 착시는 세로 방향으로 어긋난다.

## 3. 관람 위치 (필수)

이게 없으면 아나모픽 계산 자체가 성립하지 않는다. 도면에 **점으로 찍혀** 있어야 한다.

| 필요한 것 | 필드 | 비고 |
|---|---|---|
| 기준점까지 정면 방향 거리 | `eye_dist_m` | **직선거리가 아니다.** 정면 축을 따라 잰 거리 |
| 대칭축에서 좌우로 벗어난 거리 | `eye_offset_m` | + 가 오른쪽. 축 위면 0 |
| 바닥에서 눈까지 | `eye_height_m` | 서서 보면 1.5 ~ 1.7, 앉으면 1.1 ~ 1.2 |

기준점은 꺾인 벽이면 코너 정점, 다중 패널이면 지정한 이음매다.

관람 공간이 화면 정면이 아니라 한쪽으로 치우쳐 있으면 `eye_offset_m` 이 반드시 필요하다.
도면에 관람 구역(사람이 실제로 서는 범위)이 그려져 있으면 더 좋다. 그 중심이 스위트스팟이 된다.

---

## 4. LED 사양 (필수)

| 필요한 것 | 필드 | 비고 |
|---|---|---|
| 픽셀 피치 | `pitch_mm` | 이것만 있으면 크기에서 해상도를 유도한다 |
| 또는 패널별 실제 해상도 | `res_x`, `res_y` | 피치가 구간마다 다르면 이쪽을 직접 준다 |

패널마다 피치가 다르면 전개 영상 한 장이 구간별로 화소 밀도가 달라진다. 그런 경우 도면에
구간별 피치가 표시돼야 하고, `형상 점검`이 밀도 차 경고를 낸다.

---

## 5. 있으면 좋은 것

- **캐비닛 분할 도면** — LED 프로세서가 패널별로 입력을 따로 받는 경우 노드를 쪼개야 한다
- **관람 구역 범위** — 스위트스팟 한 점 말고 범위. 아나모픽이 어디까지 견디는지 판단에 쓴다
- **좌표 원점 표시** — 도면의 0점이 어디인지. 값들이 서로 어긋날 때 대조 기준이 된다
- **구조물 간섭** — 기둥, 조명, 스피커 등 시선을 가리는 것

---

## 6. 필요 없는 것

도면 제공자가 과하게 준비하지 않도록 명시해 둔다.

- 구조 계산, 하중, 앵커 사양
- 배선, 전원, 신호 계통
- 재질, 마감, 색상
- 캐비닛 내부 구조

우리는 **빛이 나오는 면의 형상과 그것을 보는 사람의 위치**만 필요하다.

## 7. 도면에 없어도 되는 것 (우리가 정한다)

| 값 | 필드 | 어떻게 정하나 |
|---|---|---|
| 정면에 둘 이음매 | `anchor_seam` | 어느 이음매를 관람자 정면에 놓을지. 보통 코너 |
| 전체 회전 | `rotate_deg` | 자동 정렬 후 미세 조정 |
| 워프 메시 분할 수 | `arc_seg` 등 | 곡률에 따라 기본값이면 대개 충분 |
| 출력 해상도 | `pitch_mm` / `wall_res_x` | 꺾인 벽은 `전개 길이 / 피치` 로 유도한다. 피치가 도면에 있으면 우리가 정할 것이 없다 |

단, 화각은 우리가 정하고 **끝나는 것이 아니라 콘텐츠 팀으로 넘겨야 한다.** 다음 절 참고.

## 8. 콘텐츠 팀에 넘길 것

도면에서 값을 받았으면, 이번엔 **영상 만드는 쪽에 숫자를 줘야 한다.**

아나모픽 변환은 벽의 기하만 되돌린다. 영상 안에 이미 찍혀 있는 원근은 못 고친다.
3D 툴에서 쓴 카메라 화각이 벽의 화각과 다르면 변환이 잘라서 맞추는데,
**잘린 것은 눈에 띄어도 원근이 어긋난 것은 눈에 안 띈다.**

`설정 편집 > [저장]` 또는 `[형상 점검]` 이 아래 블록을 찍는다. 그대로 복사해 보내면 된다.

```
콘텐츠 제작 사양  (영상 만드는 쪽에 그대로 전달할 것)
  카메라 수평 화각  48.30 deg
  카메라 수직 화각  31.62 deg
  권장 렌더 크기    7052 x 4718 px  (비율 1.494 : 1)
  안전 세로 밴드 원본 위에서 39.9% ~ 96.7% (56.8% 만 사용 가능)
  주의: 이 화각으로 만들지 않으면 변환에서 잘리고 원근이 어긋난다
```

| 항목 | 콘텐츠 팀이 할 일 |
|---|---|
| 카메라 수평·수직 화각 | 렌더 카메라의 FOV 를 여기 맞춘다 |
| 권장 렌더 크기 | 이 크기로 뽑으면 변환에서 잘려 나가는 부분이 없다 |
| 안전 세로 밴드 | 로고·자막·얼굴 등 잘리면 안 되는 것은 이 구간 안에 |

실사 촬영이면 렌즈 화각을 여기 맞춘다. 정확히 맞추기 어려우면 **더 넓게** 찍는 편이
안전하다. 좁게 찍으면 늘려야 해서 화질이 깎인다.

`영상 변환 (아나모픽)` 이 원본 해상도를 읽어 얼마나 잘려 나가는지도 로그에 남긴다.

```
원본 3840x2160 (1.778:1) -> 가상 평면 7052x4718 (1.495:1)
  가로 15.9% 가 잘려 나간다.  권장 렌더 크기로 다시 뽑으면 손실이 없다
```

## 9. 받은 뒤 확인 순서

```
1. 설정 편집 에 값 입력 -> [저장]
     화면 크기 / 비율 / 영상 파일 해상도가 도면과 맞는지 대조
2. [형상 점검]
     입사각 경고: 벽 끝이 시선에 너무 스치면 그 끝은 화소가 뭉개진다
     밀도 경고: 구간별 화소 밀도가 크게 다르면 피치/해상도를 다시 확인
3. [평면도 보기]
     법선(주황)이 눈 반대쪽을 가리키는지, 이음매가 벌어지지 않았는지 눈으로 확인
4. 격자 영상으로 영상 변환(아나모픽) -> 눈 시점으로 되돌려 보기
     격자가 곧게 펴져 나오면 형상이 맞은 것
```

4번이 최종 검산이다. 여기서 격자가 휘면 도면 어딘가를 잘못 읽은 것이다.
